# 提问与选择

## 先复用，只问缺项

先读取当前请求、会话选择及用户明确建立的项目偏好。已确定模型、来源直接沿用，包括连续编辑；新对话有适用的明确偏好时无需重选。不得从其他对话、历史图片、软件激活项猜测收费账户。

<client> profiles 返回不含密钥的来源名称和 ID。用户明确配置且授权的单一来源可直接使用；仅发现一个配置不等于授权。多来源无法区分时询问一次。

来源已确认后运行 <client> models --profile <ID>。只列实际可用的图片模型，保留 az/ 区分。指定模型存在时直接使用；不存在时解释并询问替代项。来源未明确时不遍历所有账户请求列表。

来源、模型等缺项尽量合并询问；模型目录依赖来源、无法提前列出时才分两步。信息齐全后不追加确认。

## 交互工具

使用当前宿主实际暴露且允许调用的原生提问工具处理真正的问题；失败或不可用时用简短文字等待答复。安装和日常任务不发测试问卡，不用空问题/非法参数探测。用户只要求安装时不问模型、来源或付费验收。

在 Codex 中，由对话助手直接使用当前会话工具清单中的提问工具。若清单包含并允许使用 `functions.request_user_input_async`，按实际工具签名传参。例如，账户 A 和账户 B 都已发现且用户尚未选择时，可传：

```json
{"questions":[{"title":"这次使用哪个图片 API 账户？","options":["账户 A","账户 B"]}]}
```

选项用当前任务发现的实际名称。异步调用返回后等待用户消息；预选项和工具接收回执均不代表选择。若工具未列出、当前模式不允许或宿主明确拒绝调用，直接在聊天中列出同一组选项，等待文字答复。文字选择题必须在同一条消息中逐行列出实际选项并说明回复方式。例如，若只发现两个适用模型，提问可以写成：

> 这次用哪个图片模型？
>
> 1. `gpt-image-2.6-flare`
> 2. `gpt-image-2.6-sunburst`
>
> 回复编号或完整模型 ID 即可。

账户选择采用同一格式，选项显示实际账户名称；若重名，附上可区分的非敏感来源标识。只有一个候选但仍需用户选择时也列出来。工具返回 accepted 后等待用户选择。仅在用户反馈问卡未显示或要求重发该问题时，将标题缩短为一个选择问题，保留原选项和顺序，重发一次。若用户仍看不到或明确想用文字，直接列出相同的编号选项。用户只说“这次可以了”表示问卡可见；若同一条消息也给出具体选项，则采用该选择。其他宿主按其自身工具签名处理。提问工具由宿主提供，无需在 Python、终端或便携客户端中执行同名命令。

只有用户专门要求交互诊断时才使用 ask_capability.py 记录结果。accepted、未回复或超时都不是同意。

## 授权范围

明确的生成、编辑或批量指令，可在已明确账户、模型、上传范围和预算内执行。额度说明与首次必要选择合并，不逐张重复问。额外测试、增加请求上限、换收费来源、增加敏感资料上传或未知结果后的新一轮请求才补充授权。离线自检、已有响应下载恢复无需另问。

用户明确说“此项目以后都用这些设置”时，可在指定位置保存非敏感偏好；不修改其他 skill 或 AGENTS.md 覆盖路由。普通文生图可由客户端补全已授权的本机默认组合；项目专用偏好仍按项目范围显式传入。
